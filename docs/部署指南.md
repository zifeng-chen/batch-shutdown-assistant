# 部署指南

> 版本 **v1.7.6** · 相关文档：[项目文档](项目文档.md) · [Agent 协议](Agent协议.md) · [安全说明](安全说明.md)

本文档覆盖三件事：把管理端跑起来、把 Agent 铺到门店设备上、以及后续如何升级和回滚。

---

## 1. 环境要求

### 管理端

| 项 | 要求 |
| --- | --- |
| Python | 3.10+ |
| Node.js | 18+（仅构建前端时需要） |
| 操作系统 | Linux（推荐）/ Windows |
| 端口 | 单端口对外，默认 8900 |
| 磁盘 | 数据库与上传文件共需预留 ≥ 2 GB |

### 被管理端

| 项 | 要求 |
| --- | --- |
| 操作系统 | Windows 11 家庭版（专业版亦可） |
| 权限 | 安装需管理员 |
| 网络 | 能访问管理端端口 |
| 架构 | amd64 |

> 选择 Windows 11 **家庭版**作为基线是有意的：家庭版没有域策略、没有组策略，Sysprep 行为与专业版存在差异。系统在这个基线上验证。

## 2. 管理端部署

### 2.1 获取代码

```bash
git clone https://github.com/zifeng-chen/batch-shutdown-assistant.git
cd batch-shutdown-assistant
```

### 2.2 后端依赖

```bash
cd server
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
```

### 2.3 构建前端

```bash
cd ../web
npm install
npm run build          # 产物输出到 server/static/
```

前端构建产物是必需品，不是可选项——管理端的所有页面都由 `server/static/` 提供。

### 2.4 首次启动

```bash
cd ../server
uvicorn main:app --host 0.0.0.0 --port 8900
```

首次启动会自动：

1. 初始化数据库（`lanagent.db`）；
2. 创建默认管理员 `admin / admin123`；
3. 启动离线巡检任务（每 10 秒）；
4. 启动每日维护任务（清理超期审计与过期上传）。

验证：

```bash
curl http://127.0.0.1:8900/api/health
# {"status":"ok"}
```

### 2.5 生产化：systemd

```ini
# /etc/systemd/system/lanagent-server.service
[Unit]
Description=LAN Agent Manager
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/lanagent/server
Environment=LANAGENT_DATA_DIR=/var/lib/lanagent
Environment=LANAGENT_SECRET=请替换为随机长字符串
Environment=LANAGENT_ENROLL_SECRET=请替换为随机长字符串
Environment=LANAGENT_OFFLINE_SELF_DESTRUCT_HOURS=0
ExecStart=/opt/lanagent/server/.venv/bin/python -m uvicorn main:app --host 0.0.0.0 --port 8900
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo mkdir -p /var/lib/lanagent
sudo systemctl daemon-reload
sudo systemctl enable --now lanagent-server
sudo systemctl status lanagent-server
sudo journalctl -u lanagent-server -f
```

### 2.6 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `LANAGENT_DATA_DIR` | 代码目录 | 数据目录，**生产必须指向代码目录之外**，否则升级会覆盖数据 |
| `LANAGENT_VERSION` | `1.7.6` | 版本号覆盖，一般不设 |
| `LANAGENT_SECRET` | `change-me-in-production` | JWT 签名密钥，**必须替换** |
| `LANAGENT_ENROLL_SECRET` | 由 `SECRET_KEY` 派生 | Agent 注册密钥 |
| `LANAGENT_OFFLINE_SELF_DESTRUCT_HOURS` | `0` | 离线自毁阈值，0 = 关闭 |

启动时如仍是默认 `SECRET_KEY`，日志会打印明确警告。不要忽略它。

### 2.7 反向代理（可选）

若需要 TLS 或对外统一入口，前置 Nginx。**长连接必须显式配置 Upgrade 头**，否则 WebSocket 会被降级失败，表现为"设备在线但指令无响应"。

```nginx
location / {
    proxy_pass http://127.0.0.1:8900;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 3600s;
}

location /ws/ {
    proxy_pass http://127.0.0.1:8900;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 3600s;
}
```

## 3. Agent 分发

### 3.1 安装包是现场生成的

安装包**不在仓库里**，由管理端按当前服务器地址与注册密钥即时打包：

- 界面：登录管理端 → 设备页 → 下载安装包；
- 接口：`POST /api/deploy/package`。

换服务器、换 IP、换注册密钥之后，必须重新生成安装包，旧包里的 `deploy.conf` 指向旧地址。

### 3.2 包内文件

| 文件 | 作用 |
| --- | --- |
| `LanAgent.exe` | Agent 主程序 |
| `deploy.conf` | 服务器地址 + 令牌 + 注册密钥 |
| `reinstall.bat` | 安装 / 覆盖安装入口 |
| `uninstall.bat` | 卸载 |
| `reset-password.bat` | 清空当前账户密码 |
| 安装说明.txt | 离线说明 |

### 3.3 安装步骤

1. 解压到目标电脑任意位置，`deploy.conf` 必须与 `bat` 同目录；
2. 右键 `reinstall.bat` → **以管理员身份运行**；
3. 观察输出顺序：管理员权限 → 安装包文件 → 停止旧服务 → 清理旧文件 → 复制文件 → 安装启动；
4. 出现「安装成功！服务正在运行」即完成；
5. 管理端约 10 秒内看到设备上线。

> **不要双击 `LanAgent.exe`。** 它需要 `config.json` / `deploy.conf` 才能启动，缺配置会立即退出，窗口一闪而过。

### 3.4 安装路径

```
C:\Program Files\LanAgent\
├── LanAgent.exe
├── config.json          运行期配置（device_id / token）
├── deploy.conf          安装包带入的初始配置
├── logs\agent.log       运行日志
└── data\files\          文件分发落地目录
```

旧路径 `C:\Windows\LanAgent`（1.4.9 及更早）由安装脚本与 Agent 共同清理：先迁移 `logs` 与 `data`（目标已存在则保留不动，避免覆盖在用数据），再删除旧目录。更早的 `C:\LanAgent` 由 `migrateOldData()` 处理。

### 3.5 覆盖安装

无需手动卸载。直接右键 `reinstall.bat` 管理员运行。脚本会：

1. 停止并删除旧服务注册；
2. 结束残留 `LanAgent.exe` 进程（**按完整路径匹配**，不会误杀解压目录里正在运行的安装程序）；
3. 删除旧 `LanAgent.exe` / `config.json` / `deploy.conf`；
4. 复制新版本、重建并启动服务；
5. 保留 `logs` 与 `data`；
6. 清理更早路径的遗留。

### 3.6 安装日志

脚本每一行输出都同步写入**安装包所在目录**下的 `安装日志.txt`。终端窗口意外关闭也不影响，可直接打开查看卡在哪一步。若该目录不可写，自动回退到 `%TEMP%`。

这是刻意的设计：现场是 U 盘安装，把日志写在 U 盘上，拔下来就能回传，不需要让现场人员去翻系统目录。

### 3.7 批量分发

推荐两种方式：

| 方式 | 做法 | 适用 |
| --- | --- | --- |
| U 盘逐个装 | 拷包到 U 盘，逐台运行 `reinstall.bat` | 少量设备、首次重装 |
| 远程推送 | `psexec` 或域下发运行 `reinstall.bat /silent` | 已在线设备批量更新 |

首次铺开时设备还不在管理端里，只能现场安装；后续更新优先用管理端的"推送升级"。

## 4. 升级

### 4.1 升级管理端

```bash
cd /opt/lanagent
sudo systemctl stop lanagent-server

# 备份数据（重要）
sudo tar czf /var/backups/lanagent-$(date +%F).tar.gz -C /var/lib lanagent

git pull
cd server && . .venv/bin/activate && pip install -r requirements.txt
cd ../web && npm install && npm run build

sudo systemctl start lanagent-server
curl http://127.0.0.1:8900/api/health
```

### 4.2 升级 Agent

**方式一：管理端推送（推荐）**

1. 管理端上传新版 `LanAgent.exe`（`POST /api/upgrade/upload`）；
2. 设备页选择目标设备或"全部在线设备"；
3. 推送升级，观察任务进度。

Agent 侧流程：校验下载来源同源 → 下载 → 校验 → 替换 exe → 重启服务。全程不需要人工。

**方式二：现场覆盖安装**

按 3.5 节操作。

### 4.3 版本一致性

管理端与 Agent 的版本**必须匹配**。历史上出过多次"服务端返回结构与客户端解析不一致"的问题，症状是心跳 200 但关键字段为空。

升级顺序建议：**先升管理端（向后兼容），再升 Agent**。反过来会让新 Agent 遇到旧服务端，字段缺失。

### 4.4 升级安全红线

改命令通道协议或令牌传输方式时，必须按这个顺序：

1. 管理端做**双模兼容**（同时接受新旧形式）；
2. 推送升级，确认全部 Agent 已切到新版本；
3. 再关闭旧入口。

顺序颠倒会让升级过程中设备成批掉线，且无法远程恢复——只能逐台现场处理。

## 5. 回滚

### 5.1 回滚管理端

```bash
sudo systemctl stop lanagent-server
sudo tar xzf /var/backups/lanagent-YYYY-MM-DD.tar.gz -C /var/lib
cd /opt/lenovo-store-operations && git checkout <上一个 tag>
sudo systemctl start lanagent-server
```

数据库结构与代码版本需匹配。跨大版本回滚前先确认没有不兼容的结构变更。

### 5.2 回滚 Agent

`resources/agent/` 下保留了历史版本备份（`LanAgent.exe.bak-<版本>`）。回滚即用旧 exe 替换后重装：

1. 取对应版本的 `LanAgent.exe`；
2. 与当前 `deploy.conf`、`reinstall.bat` 放同一目录；
3. 管理员运行 `reinstall.bat`。

### 5.3 回滚前的判断

先确认问题在新版本还是环境：

- 只有一台设备异常 → 先查该设备的日志与网络，不要急着回滚整批；
- 全部设备同时异常 → 大概率是管理端问题，查服务端日志；
- 升级后立即异常 → 回滚。

## 6. 数据备份

### 6.1 需要备份什么

| 项 | 路径 | 说明 |
| --- | --- | --- |
| 数据库 | `$LANAGENT_DATA_DIR/lanagent.db` | 设备、任务、审计全在这 |
| 上传文件 | `$LANAGENT_DATA_DIR/uploads/` | 升级包与分发文件 |
| 配置 | `deploy.conf` 模板、环境变量 | 注册密钥丢失需重新生成安装包 |

### 6.2 SQLite 备份注意

**不要只复制主数据库文件。** WAL 模式下还有 `-wal` 与 `-shm`，只拷主文件会得到不一致的快照。

```bash
# 正确做法：用 SQLite 在线备份
sqlite3 "$LANAGENT_DATA_DIR/lanagent.db" ".backup '/var/backups/lanagent-$(date +%F).db'"

# 或者停服后整目录打包
sudo systemctl stop lanagent-server
sudo tar czf /var/backups/lanagent-$(date +%F).tar.gz -C "$LANAGENT_DATA_DIR" .
sudo systemctl start lanagent-server
```

### 6.3 定时备份

```bash
# /etc/cron.daily/lanagent-backup
#!/bin/sh
mkdir -p /var/backups/lanagent
sqlite3 /var/lib/lanagent/lanagent.db ".backup '/var/backups/lanagent/db-$(date +%F).db'"
find /var/backups/lanagent -name 'db-*.db' -mtime +30 -delete
```

## 7. 部署验收清单

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| 1 | 健康检查 | `GET /api/health` 返回 `{"status":"ok"}` |
| 2 | 管理员密码 | 已从 `admin123` 改掉 |
| 3 | 密钥 | `LANAGENT_SECRET` 与 `LANAGENT_ENROLL_SECRET` 均为随机值 |
| 4 | 数据目录 | 指向代码目录之外 |
| 5 | 安装包 | 由当前管理端重新生成，`deploy.conf` 地址正确 |
| 6 | Agent 上线 | 管理端 10 秒内可见，状态在线 |
| 7 | 心跳日志 | `[heartbeat] saved device_id=…` |
| 8 | 长连接日志 | `[ws] connected` |
| 9 | 指令验证 | `status` 与 `sysinfo` 能正常回传 |
| 10 | 离线判定 | 停止 Agent 服务，15 秒后列表标记离线 |
| 11 | 日志策略 | `agent.log` 只保留 10 分钟，断开后只留一条断开记录 |
| 12 | 覆盖安装 | 旧版本机器上直接运行 `reinstall.bat` 成功，数据与日志保留 |

第 9 项是关键：**上线不等于可用**。设备显示在线只证明心跳通，必须实际下发一条 `status` 并拿到回传，才算整条链路打通。
