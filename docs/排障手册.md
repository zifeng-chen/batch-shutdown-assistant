# 排障手册

> 版本 **v1.7.6** · 相关文档：[Agent 协议](Agent协议.md) · [部署指南](部署指南.md) · [项目文档](项目文档.md)

按现象索引。先定位断在哪一环，再看对应小节，不要一上来就重装。

---

## 0. 先分清三件事

排查前必须分清这三层，否则会浪费时间：

```
① 设备上线了吗？        ← 心跳（HTTP）决定
② 能收到指令吗？        ← 长连接（WebSocket）决定
③ 指令执行成功了吗？    ← 指令逻辑与权限决定
```

| 现象 | 断在哪一层 |
| --- | --- |
| 列表里根本没有这台设备 | ① 心跳没通 |
| 显示在线，但下发指令无反应 | ② 长连接没通 |
| 收到指令但回报失败 | ③ 执行失败 |

这三层互相独立。心跳通不代表长连通，长连通不代表指令能执行。

**任何排查的第一步都是拿日志。**

```
C:\Program Files\LanAgent\logs\agent.log
```

日志只保留最近 10 分钟，所以**要在复现之后立刻取**，隔一会儿就没了。

正常链路的两行标志：

```
[heartbeat] saved device_id=26 (action=ok code=0)
[ws] connected
```

看到这两行说明①②都通了，问题在③。

## 1. 设备不上线

### 1.1 检查清单

| 步骤 | 命令 / 位置 | 判断 |
| --- | --- | --- |
| 服务是否在跑 | `sc query LanAgent` | 应为 `RUNNING` |
| 安装目录是否存在 | `C:\Program Files\LanAgent\` | 应有 `LanAgent.exe` 与 `deploy.conf` |
| 配置是否正确 | 查看 `deploy.conf` 的服务器地址 | 应指向当前管理端 IP 与端口 |
| 网络是否可达 | 浏览器打开 `http://<管理端IP>:<端口>/api/health` | 应返回 `{"status":"ok"}` |
| 注册密钥是否正确 | 安装包是否由当前管理端生成 | 换过密钥需重新生成 |
| 日志有无报错 | `logs\agent.log` | 看最后一屏 |

### 1.2 常见原因

**`401 Enrollment secret required`**

设备首次注册时没带正确的 `X-Enroll-Secret`。安装包的 `deploy.conf` 来自旧管理端，或管理端换过 `LANAGENT_ENROLL_SECRET`。

处理：在管理端重新生成安装包，重新安装。

**`401 Invalid agent token`**

同 IP 上已有一条记录且令牌不一致，同时没提供有效注册密钥。

处理：确认是本人重装（不是他人抢占）。若是重装，用最新安装包重装；若确认旧记录已无用，在管理端删除该设备后重装。

**`sc query` 显示服务存在但不运行**

```bash
sc start LanAgent
```

启动后立即查日志。若日志连一行都没有，说明连日志初始化都没走完——检查 `C:\Program Files\LanAgent\logs` 目录是否存在且可写。

**服务根本不存在**

安装没成功。回到安装步骤，管理员运行 `reinstall.bat`，看 `安装日志.txt` 卡在哪一步。

## 2. 显示在线但指令无响应

**这是历史上出现最多的一类问题。** 心跳走 HTTP，指令走 WebSocket，两条通道可以一个通一个不通。

### 2.1 按顺序排查

| # | 检查 | 判断 |
| --- | --- | --- |
| 1 | 日志有无 `[ws] connected` | 没有 → 长连接没建立 |
| 2 | 日志有无 `[ws] waiting for device_id...` | 有 → 心跳没回填 device_id，转 2.3 |
| 3 | 日志有无 `[ws] connect failed` | 有 → 握手失败，转 2.4 |
| 4 | 设备上是否配了系统代理 | 有 → 转 2.2 |
| 5 | 前置 Nginx 是否配了 Upgrade 头 | 没配 → 转 2.5 |

### 2.2 系统代理导致单通道被拦

**现象**：心跳正常（设备在线），长连接一直失败。

**原因**：设备上存在 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量或系统代理设置。心跳 HTTP 走代理，WebSocket 直连，两条通道行为不一致。

**已处理**：Agent 内置的 HTTP 客户端与 WebSocket 拨号器都显式设置 `Proxy: nil`，两条通道统一走直连。

**若仍出现**：确认现场 Agent 版本 ≥ 1.7.x。旧版本没有这个设置。

### 2.3 `waiting for device_id` 一直循环

**现象**：日志反复出现

```
[ws] waiting for device_id from heartbeat... (server="http://…" device_id="" token=true)
```

注意括号里的三个值，它们直接指出断点：

| 括号内容 | 含义 |
| --- | --- |
| `device_id=""` `token=false` | 配置完全没读到 |
| `device_id=""` `token=true` | 有 token 但心跳没回填 device_id |
| `server=""` | 配置读取失败 |

**根因一：心跳响应结构解析失败**

历史上最隐蔽的一个 bug。管理端把 `device_id` 放在 JSON 里返回（数字类型），早期 Agent 用 `string` 接收，`json.Unmarshal` 报错但错误被静默吞掉，`device_id` 永远是空。

症状极具误导性：**心跳 HTTP 200、服务端日志显示心跳正常收到，但客户端拿不到 device_id。**

确认方式：日志里搜 `[heartbeat] saved device_id=`。没有这一行就是没解析成功。

处理：升级到 1.7.6 及以上。该版本用 `interface{}` 接收再归一化，并补充了 `[heartbeat] 解析响应失败` 的显式日志。

**根因二：安装目录不可写**

`config.json` 落在 `C:\Program Files\LanAgent\`，若该目录不可写（杀软拦截、权限异常），device_id 每次都写不进磁盘。

处理：1.7.x 已加内存副本兜底（`liveCfg`），磁盘失败时长连接改用内存值。若日志出现 `[heartbeat] 保存 device_id 失败`，说明确实不可写，检查杀软白名单。

### 2.4 `[ws] connect failed`

| 日志内容 | 原因 | 处理 |
| --- | --- | --- |
| `dial tcp …: connectex: No connection could be made` | 端口不通 | 查防火墙、确认管理端端口 |
| `websocket: bad handshake` + 401 | token 无效或已轮换 | 重装或用最新安装包 |
| `dial tcp …: i/o timeout` | 网络不可达或代理干扰 | `Test-NetConnection <IP> -Port <端口>` |
| `x509` / TLS 相关 | 反代证书问题 | 检查证书链，或内网直连测试 |

**token 轮换场景**：设备重装后管理端轮换了 token，而 Agent 内存里还是旧值。1.7.6 起心跳会同步响应里的 token 并重建认证头；旧版本会一直 401。

### 2.5 前置代理吞掉 WebSocket

若管理端前有 Nginx/Apache，必须显式转发 Upgrade：

```nginx
proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
proxy_read_timeout 3600s;
```

漏掉 `Upgrade` 头时，握手被降级，长连接建立不起来，但心跳（普通 POST）完全正常——症状和 2.2 一模一样。

### 2.6 指令下发成功但设备毫无反应

**指令名大小写问题**。管理端下发时统一转小写，Agent 按小写匹配；历史版本曾下发大写 `SHUTDOWN`，全部命中 `default` 分支并回报 `unknown action`。

查任务详情里设备回报的 `output`：出现 `unknown action` 就是这个问题。升级到已修复版本。

## 3. 安装相关

### 3.1 窗口一闪就关闭

**原因一：直接双击了 `LanAgent.exe`**

它需要 `config.json` / `deploy.conf`，缺配置立即退出。**正确入口是 `reinstall.bat`（右键，管理员运行）。**

**原因二：bat 标签写在 `if (...)` 块里**

批处理中 `goto :label` 跳进括号块内会失败，脚本直接结束。当前版本已将所有标签移出 `if` 块，并改用 `pause >nul` + `goto :eof` 收尾。若出现此现象，说明用的是旧安装包。

**原因三：全局 `taskkill` 杀掉自己**

旧版用 `taskkill /f /im LanAgent.exe`，那是按映像名全局匹配，会连带杀掉解压目录里正在运行的安装程序，脚本中途被中断。

当前版本改为按完整路径匹配（只结束可执行文件位于目标目录的进程）。若旧包仍出现此现象，换新包。

### 3.2 按回车窗口也不关

旧版 `:log` 分支在参数为空时调用了 `echo`（无参数会打印 `ECHO 处于打开状态`），且顶层 `exit /b` 不可靠。

当前版本用 `pause >nul` + `goto :eof` 收尾。仍出现则说明是旧包。

### 3.3 提示文件被占用

杀毒软件锁定了 `LanAgent.exe`。

处理顺序：

1. 把 `C:\Program Files\LanAgent` 加入杀软白名单；
2. 重启电脑；
3. 开机后**立即**运行 `reinstall.bat`（趁杀软还没扫描）。

### 3.4 覆盖安装后数据或日志丢了

正常行为是**保留** `logs` 与 `data`。若丢失：

- 检查是否手动删除了 `C:\Program Files\LanAgent` 整个目录；
- 从旧路径迁移时，若目标目录已存在同名子目录会**保留不动**（避免覆盖在用数据），此时旧目录里的内容会被删除——先手动备份。

### 3.5 安装在 `C:\Program Files` 权限不足

1.4.9 及更早版本把安装目录放在 `C:\Windows\LanAgent`，出现过日志目录创建失败、采集不到信息等问题。1.5.0 起改回 `C:\Program Files\LanAgent`。

若现场是旧路径，直接管理员运行新包的 `reinstall.bat`，脚本会自动迁移并清理。

## 4. 指令执行失败

### 4.1 采集不到硬件信息（`sysinfo`）

| 检查 | 说明 |
| --- | --- |
| Agent 版本 | 低于 1.6 的版本采集字段不全 |
| 服务权限 | 必须以 LocalSystem 运行，普通用户权限采不到序列号 |
| WMI 是否可用 | 系统 WMI 服务被禁用会导致采集为空 |
| 日志 | 搜 `sysinfo` 看是否有异常 |

### 4.2 弹窗不显示（`hostmsg`）

| 原因 | 处理 |
| --- | --- |
| 会话隔离 | 服务在 Session 0 运行，弹窗要投到交互式会话 |
| 参数缺失 | 确认 `title` / `body` 有值 |
| 超时太短 | `timeout` 设得太小，窗口刚出现就关了 |

### 4.3 关机/重启不执行

| 原因 | 处理 |
| --- | --- |
| 权限 | 服务需 LocalSystem |
| 有程序阻止关机 | 检查是否有未保存文档的阻塞 |
| Sysprep 次数耗尽 | 用 `status` 看 `rearm_count`，`-1` 表示取不到，`0` 表示已用完 |

### 4.4 Sysprep 后登录提示密码不正确

这是 Sysprep 的已知副作用：OOBE 后凭据被改写。

处理：用已知密码进入桌面后，管理员运行 `reset-password.bat`，输入 `Y` 确认，显示「密码已清空」后重启，即可空密码进入。

该脚本只清空**当前登录账户**，不影响其他账户。

### 4.5 回报 `unknown action`

指令名大小写问题，见 2.6。

## 5. IP 显示异常

### 5.1 IP 为空

**这是设计行为，不是 bug。**

Agent 枚举网卡后按优先级排序，若没有任何有效地址（典型：机器未联网，只有 169.254 链路本地或回环），上报空字符串，**不写 `127.0.0.1`**。

管理端收到空 IP 时**保留上一次的有效 IP**。设备恢复联网后，下一次心跳自动回推正确地址。所以看到 IP 为空时先确认设备是否真的没网。

### 5.2 IP 跳来跳去

多网卡机器（有线 + 无线 + 虚拟网卡 + 蓝牙）的枚举顺序不稳定。

优先级规则：

```
192.168.x.x  >  10.x.x.x  >  其它  >  172.16–31.x.x（虚拟网卡）  >  无效
```

若仍跳变，说明存在同优先级的多个地址。检查是否有多个真实网卡同时在线。

### 5.3 IP 不对但能通

确认 `ip` 字段是否是管理端保留的历史值。可以让设备重装或等待下一次心跳刷新。

## 6. 列表与界面

### 6.1 排序不是数字顺序

后端按 IP **数值**排序（`ip_sort_key`），跨网段正确：`192.168.2.9` 排在 `192.168.2.10` 之前。

非法或缺失 IP 排到末尾，并按主机名稳定次级排序。若看到字符串序（`.10` 在 `.9` 前面），说明前端拿到的是未排序结果或版本过旧。

### 6.2 在线设备不在最上面

界面把在线与离线分成两组渲染（`onlineDevices` / `offlineDevices`），在线固定在上。若混在一起，检查前端版本。

### 6.3 设备显示离线但其实在跑

心跳超过 15 秒未更新即标记离线。可能原因：

- 网络抖动；
- 设备休眠（Windows 睡眠会暂停服务）；
- 管理端刚重启，等待下一次心跳（最长 15 秒）。

## 7. 日志判读速查

| 日志行 | 含义 | 正常？ |
| --- | --- | --- |
| `[log] 日志文件: …` | 日志初始化成功 | ✓ |
| `[heartbeat] saved device_id=26 (action=ok code=0)` | 心跳注册成功、主键已回填 | ✓ |
| `[ws] connected` | 长连接建立，可收指令 | ✓ |
| `[ws] connecting to ws://…` | 正在连 | ✓ 过渡态 |
| `[ws] waiting for device_id from heartbeat...` | 心跳未回填 device_id | ✗ 见 2.3 |
| `[heartbeat] 解析响应失败` | 响应结构与预期不符 | ✗ 版本不匹配 |
| `[heartbeat] 解析 data 失败` | 信封内层解析失败 | ✗ 看原始片段 |
| `[heartbeat] 保存 device_id 失败` | 安装目录不可写 | ✗ 见 2.3 |
| `[ws] connect failed` | 握手失败 | ✗ 见 2.4 |
| `[log] 与管理端断开 …` | 已断开，后续静默 | ✗ 见 7.1 |

### 7.1 日志为什么不再增长

**这是设计行为。** 与管理端断开后停止写入业务日志，只在断开那一刻记一条带时间的记录，然后静默。

目的是让回传的日志永远是"最近发生了什么"，而不是一个需要翻很久的历史文件。

判断方式：日志最后一行是 `[log] 与管理端断开 <时间>`，说明断开发生在该时间点。

### 7.2 日志只有 10 分钟

保留窗口是 10 分钟。超出的行会被裁掉。所以排查时**要复现完立刻取日志**。

### 7.3 日志在哪里

```
C:\Program Files\LanAgent\logs\agent.log
```

安装日志（不是运行日志）在**安装包所在目录**的 `安装日志.txt`，U 盘安装时就在 U 盘里。

## 8. 服务端排查

### 8.1 看服务端日志

```bash
sudo journalctl -u lanagent-server -f
```

关键日志：

| 日志 | 含义 |
| --- | --- |
| `Auto-registered new device: …` | 新设备注册成功 |
| `Device … re-enrolled: token rotated` | 重装接管成功 |
| `Rejected heartbeat for device …: token mismatch` | 令牌不一致被拒 |
| `Rejected unregistered device enrollment` | 无注册密钥被拒 |
| `Heartbeat timeout: N device(s) marked offline` | 离线巡检生效 |

### 8.2 数据库检查

```bash
sqlite3 "$LANAGENT_DATA_DIR/lanagent.db" \
  "SELECT id, hostname, ip, status, agent_version, last_heartbeat FROM devices ORDER BY ip;"
```

确认设备记录存在、`status` 正确、`last_heartbeat` 是近期的。

### 8.3 健康检查

```bash
curl http://127.0.0.1:8900/api/health
```

不通说明服务没起来，先查 `systemctl status`。

## 9. 升级相关

### 9.1 推送升级后设备离线

| 原因 | 处理 |
| --- | --- |
| 下载来源校验失败 | 升级包 URL 必须指向当前管理端，检查服务器地址 |
| 替换 exe 时被占用 | 服务需先停止；检查服务恢复策略 |
| 新版本有 bug | 用 `resources/agent/` 里的旧版本 exe 现场回滚 |

### 9.2 升级后版本号没变

Agent 重启后读的是新 exe。若版本号仍旧：

1. 确认 `LanAgent.exe` 的修改时间已更新；
2. 确认没有多个 `LanAgent.exe`（旧路径残留）；
3. 查日志开头的 `[log]` 行确认运行的是哪个路径。

### 9.3 版本不一致

管理端与 Agent 版本必须匹配。历史上多次出现"服务端返回结构变了、客户端还按旧结构解析"，症状是心跳 200 但字段为空。

升级顺序：**先升管理端，再升 Agent。**

## 10. 升级到 1.7.6 的验收要点

1.7.6 修的是"心跳正常但 device_id 永远为空"的根因。装完后必须看到：

```
[heartbeat] saved device_id=26 (action=ok code=0)
[ws] connected
```

然后下发一条 `status`，确认能拿到回传。**两行日志都出现且指令有回传，才算真正修复。**

若只看到第一行、没有第二行，看 2.4；两行都没有，看 1.1。
