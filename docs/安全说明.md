# 安全说明

> 版本 **v1.7.6** · 相关文档：[项目文档](项目文档.md) · [Agent 协议](Agent协议.md) · [部署指南](部署指南.md)

本文档描述 LAN Agent 的安全模型、威胁边界、已落地的加固措施与仍然存在的限制。上一版基于 2026-10-07 的两次代码审计，其中列出的高危项已全部修复并核实，本文档取代那两次审计快照。

---

## 1. 风险模型

需要先说清楚一件事：**Agent 以 SYSTEM 权限常驻在被管控主机上**，它是整条攻击链的终点。

```
攻击者 → 管理端 → 命令通道 → Agent(SYSTEM) → 被管控主机
```

因此真正决定安全水位的是两个问题：

1. **谁能下达指令** —— 管理端的认证与授权；
2. **Agent 信任谁** —— Agent 对服务端下发内容的校验强度。

Agent 对"服务器"有绝对信任：任何能冒充服务器或篡改命令通道消息的人，都能让所有被管控主机执行任意代码。所以 Agent 侧的下载来源校验、路径约束和令牌管理是重中之重，而不是可选优化。

### 威胁边界

| 在范围内 | 不在范围内 |
| --- | --- |
| 未授权者访问管理端 | 物理接触设备 |
| 伪造心跳注册设备 | 已取得 SYSTEM 权限后的横向移动 |
| 冒充服务器诱导 Agent 下载 | 供应链攻击（Go 依赖、npm 依赖） |
| 命令通道窃听与篡改 | 操作系统自身漏洞 |
| 路径穿越写入越权目录 | 内网 DNS / ARP 基础设施被完全控制 |
| 重放已删除设备的令牌 | — |

**传输层假设**：默认部署在受控内网，HTTP 明文。这不是疏忽——长连接与心跳同源、URL 校验已限制到管理端主机，但**局域网内具备 ARP 欺骗或中间人能力者仍可篡改明文流量**。若部署环境不满足这个假设，必须在前面加 TLS 反向代理。

## 2. 已落地的加固

### 2.1 管理端认证

| 措施 | 实现 |
| --- | --- |
| 密码存储 | bcrypt 哈希，不存明文 |
| 会话 | JWT，`TOKEN_EXPIRE_MINUTES = 60 * 24 * 30` |
| 登录限流 | 按 (IP, 用户名) 计数，5 次失败锁定 5 分钟并指数退避；失败与锁定写审计 |
| 令牌比较 | `hmac.compare_digest` 恒定时间比较，避免时序侧信道 |
| 默认凭证 | 启动时检测到默认 `SECRET_KEY` 会在日志打警告 |

### 2.2 Agent 身份与注册

Agent 的信任链是这样建立的：

1. 安装包内的 `deploy.conf` 携带每台设备独立的 token 与预共享注册密钥；
2. 首次注册时必须携带正确的 `X-Enroll-Secret`，否则 `401 Enrollment secret required`——这堵住了"匿名伪造设备进列表"的路；
3. 令牌不一致时，只有**记录已软删除**或**注册密钥正确**才允许接管，否则 `401 Invalid agent token`——这堵住了"用别人的 IP 抢占已有设备"的路；
4. 注册临界区加锁，并发心跳不会产生重复记录。

### 2.3 命令通道

- 长连接握手校验 Bearer token，失败以关闭码 `4001` 断开；
- 令牌同时出现在 query 与 header，**query 形式会被中间代理与访问日志记录**，这是已知残留风险（见第 4 节）；
- 指令分发是**严格的白名单 switch**，没有把参数拼进 shell 执行；
- 指令名一律小写匹配，大写形式命中默认分支并回报 `unknown action`。

### 2.4 Agent 侧下载来源校验

**历史最高危问题**：早期版本 Agent 无条件信任服务端下发的下载 URL，任何人冒充服务器即可让全部被管控主机下载并执行任意程序。

现在 `validateServerURL()` 在 `upgrade` 与 `file_push` 两条路径上都强制校验：下载地址必须指向当前管理服务器（同一主机、同一端口），否则拒绝执行。测试覆盖了三类绕过尝试：跨端口、跨主机 IP、非 HTTP 协议。

### 2.5 路径约束

`file_push` 的目标路径经 `safeJoinUnder(baseDir, name)` 处理，要求拼接结果仍在允许的根目录之下。含 `..\..` 或绝对路径的 `Filename` 会被拒绝，不会逃出目标目录。

### 2.6 静态资源与 SPA 兜底

`GET /{full_path:path}` 对候选路径做 `realpath` 后校验 `commonpath` 必须等于静态根目录，`../` 及其编码变体都被挡住。

### 2.7 进程操作

覆盖安装与迁移需要结束残留的 `LanAgent.exe`。**不使用 `taskkill /f /im`**——那是全局按映像名匹配，会连带杀掉解压目录里正在运行的同名安装程序，导致安装脚本中途被中断。

改为 `killAgentsUnder(dir)`：先按映像名取 PID，再逐个查 `ExecutablePath`，只有路径前缀匹配指定目录才结束。既解决了文件占用，也不会误伤。

### 2.8 传输一致性

Agent 的心跳 HTTP 客户端与 WebSocket 拨号器都显式设置 `Proxy: nil`。

这不只是稳定性问题，也是安全问题：设备上若存在 `HTTP_PROXY`/`HTTPS_PROXY`，心跳会经代理而长连接走直连，两条通道信任路径不一致——一个恶意的代理配置可以只拦截心跳而放行长连接，或者相反。统一走直连让行为可预期。

### 2.9 上传与存储

| 项 | 措施 |
| --- | --- |
| 上传体积 | 单文件 500 MB 上限 |
| 上传内容 | 校验 DOS/PE 头（`MZ` 开头且 `e_lfanew` 处为 `PE\0\0`） |
| 上传留存 | 保留最近 20 份，超期自动清理 |
| 审计留存 | 180 天 / 20 万条上限，每日维护任务清理 |
| 任务输出 | 截断 10 万字符，防止单条结果撑爆数据库 |
| 数据库 | SQLite WAL + `busy_timeout=5000` + `synchronous=NORMAL` |

### 2.10 审计

关键操作写入审计表：登录失败与锁定、设备增删、指令下发、升级推送、配置变更。审计记录同步清理，不会无限增长。

## 3. 加固清单（部署前逐项确认）

| 优先级 | 项 | 做法 |
| --- | --- | --- |
| P0 | 管理员密码 | 首次登录立即修改，不要保留 `admin123` |
| P0 | `SECRET_KEY` | 设置 `LANAGENT_SECRET` 为随机长字符串 |
| P0 | 注册密钥 | 设置 `LANAGENT_ENROLL_SECRET`，不要依赖默认派生值 |
| P0 | 安装包外传 | `deploy.conf` 含注册密钥，视为凭证管理 |
| P1 | 数据目录 | `LANAGENT_DATA_DIR` 指向代码目录之外 |
| P1 | 网络暴露 | 只在内网；管理端不要暴露到公网 |
| P1 | 端口收敛 | 单端口对外，减少攻击面 |
| P2 | 传输加密 | 环境不满足内网假设时，前置 TLS 反向代理 |
| P2 | 版本对齐 | 现场 Agent 与管理端版本一致，避免旧版本缺失校验 |

## 4. 已知限制

以下问题在代码中仍然存在，使用前应当知情。

| 项 | 说明 | 影响 |
| --- | --- | --- |
| 传输明文 | 默认 HTTP，未强制 TLS | 内网中间人可篡改流量 |
| token 经 query | 长连接 token 出现在 URL query，会被代理与访问日志记录 | 日志泄露即令牌泄露 |
| 无数字签名校验 | 上传的 exe 只校验 PE 头，不验签名 | 有管理端权限者可推送任意 exe |
| JWT 不可撤销 | 无主动失效机制，靠 30 天过期 | 令牌泄露后窗口较长 |
| 本地配置明文 | `config.json` 中 token 未加密 | 有本机文件读取权限者可窃取 |
| 时间字段本地时区 | 使用北京时间 naive datetime | 跨时区部署需注意 |

这些不是"待办清单"——它们是有意的取舍。前四项需要三端协同改造（管理端双模兼容 → 推送升级全部 Agent → 关闭旧口子），在设备未全部升级前贸然改协议会让存量设备掉线。

## 5. 升级安全注意事项

改命令通道协议或令牌传输方式时，必须按这个顺序：

1. 管理端先做**双模兼容**（同时接受新旧形式）；
2. 推送升级，确认全部 Agent 已切换到新版本；
3. 再关闭旧形式的入口。

顺序反过来，升级过程中设备会成批掉线且无法远程恢复——只能逐台现场处理。
